# Active assistant operability closure

Novo must refresh tracked project context on its existing 15-minute cadence, offer Codex work on this Windows 10 PC only when the native sandbox proves its filesystem boundary, and let the user approve a narrowly scoped GitHub issue or Vercel redeployment from the project work card.

The GitHub schedule remains the 15-minute scheduler. A Vercel Hobby cron runs at most once daily, so it cannot replace that cadence. Do not report automatic freshness as operational until GitHub records a `schedule` run that reaches the production endpoint successfully.

Windows Codex work uses the provisioned `elevated` sandbox fallback, exact workspace write access, denied credential/environment paths, and disabled network access. The Companion must continue to advertise the capability as unavailable if its filesystem containment probe fails. Claude remains unavailable unless its CLI and the same containment checks are present.

External writes use only two typed operations: create an issue in an explicitly named GitHub repository, and redeploy an explicitly named existing Vercel deployment to either Preview or Production. Novo stores the exact operation and fingerprint before dispatch, requires the existing owner-bound confirmation, audits every decision, prevents duplicate dispatch, and marks timeouts or lost responses uncertain instead of retrying them automatically. The Twin refreshes provider observations after a confirmed write when possible.

No provider token, arbitrary URL, shell command, or model-authored API request is accepted as an operation. GitHub write access and Vercel project selection are verified on the server before dispatch.
